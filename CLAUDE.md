# Архитектура и модульность

- **Разделение слоёв (SoC).** Логика, модели данных и UI/представление живут в разных файлах. Python: бизнес-логика в `common/`, тонкие обёртки-ноды в `nodes/`. Фронт: логика в `composables`/`stores`, представление в `components`. Файл, переросший свою задачу, — сначала рефактор в папку с под-файлами, потом новый код.
- **Паттерн `_helpers`.** Тяжёлую логику ноды держать не в `node_*.py`, а в отдельном модуле `common/` (или рядом лежащем `_*_helpers.py`). `node_*.py` — тонкий: INPUT_TYPES, RETURN_TYPES, вызов логики.
- **Чистые импорты.** В новых файлах импортировать только строго необходимое, чтобы граф зависимостей оставался тонким.
- **Крупные изменения — сначала план.** Перед архитектурным рефактором или сознательным нарушением SRP — краткое резюме на подтверждение (dry run). Мелкие правки — менять только нужные строки, не переписывать файл целиком.

# Работа со стыком ComfyUI

Пак живёт внутри чужого приложения. Почти все дефекты, доехавшие до пользователя, — не ошибки в нашей логике, а неверные догадки о том, как ведёт себя хост. Правила ниже оплачены конкретными багами.

- **Радиус поражения называть до правки.** Перед изменением сказать вслух: это одна нода или общий слой. Файл в `nodes2/`, `nodes2/host/` или `components/widgets/` — это все ноды пака сразу, и проверять надо минимум на трёх разных. «Чиню Cleaner» и «правлю `domWidgetHost`» — разные по риску задачи, даже если повод один.
- **Спрашивать хост, а не додумывать за него.** Тест, который зовёт `execute()` напрямую, доказывает только внутреннюю непротиворечивость наших убеждений: шим Cleaner был зелёным и не мог сработать никогда. Питон — гонять вызов через `tests/executor_harness.py`, он вызывает настоящий `execution.py`. Фронт — через `frontend/tests/fakes/comfyHost.ts`, а не заводить очередной самодельный узел в файле теста.
- **Скрытые значения у V3-ноды приходят через `cls.hidden`.** Параметром — никогда. Параметр с таким именем всегда останется `None`; так молча умерли метаданные превью и два прогресс-бара.
- **Никаких глобальных патчей хоста без явного обоснования.** Слушатель на `window`, обёртка чужого прототипа, перехват метода ядра — сначала вопрос «можно ли вообще без этого». Наш `wheel` на `window` глушил колесо у всех остальных паков; обёртка `getExtraMenuOptions` с поздним чтением рекурсивно убивала контекстное меню.
- **Перед живой проверкой в ComfyUI — снимок графа на диск.** Открытый воркфлоу может быть временным и жить только в localStorage браузера: добавление своей ноды перезаписывает черновик, а `graph.remove()` его не возвращает. Сначала сериализовать граф в файл, потом трогать холст. Ещё лучше — заводить отдельный пустой воркфлоу под проверку и закрывать его после.
- **Правку в `frontend/src` заканчивать сборкой.** `frontend/dist` лежит в гите и именно он уезжает в реестр — несобранный `dist` отправит пользователям старый бандл, и все остальные проверки при этом пройдут.


Фронт — из `frontend/`: `npm test` (vitest), `npm run typecheck`, `npm run build` (сборка + пересчёт `dist/.source-hash`), `npm run check:bundle` (сверить, что `dist` собран из текущего `src`), `npm run test:all` — всё разом. # Как вести работу

Владелец проекта не программист. Веду я: предлагаю следующий шаг сам, а не жду указаний; объясняю бытовым языком, термин — только с расшифровкой.

- **Коротко и по делу.** Пользователь не программист и не обязан разбираться в деталях правки. В ответе — что сделано и что это значит для него, без хода рассуждений, списков вариантов и внутренней механики (какие файлы читал, что перепроверял). Полная версия — только если он сам спросит подробности.
- **Граница самостоятельности.** Правки, тесты, сборка `frontend/dist`, `git commit` в ветку — делаю сам и просто сообщаю результат. Спрашиваю перед `git push` и перед живой проверкой в открытом ComfyUI (можно потерять черновик воркфлоу).
- **Думать на шаг вперёд.** Закончив задачу, назвать, что логично сделать следующим и почему. Одно предложение с обоснованием, а не список вариантов на выбор.
- **Возражать до, а не после.** Если просьба ведёт к граблям — сказать одной фразой и предложить, как лучше. Настоял — делаю как просили, без повторов.
- **Знание ComfyUI — из исходников хоста, не по памяти.** Хост меняется от версии к версии, память врёт молча. Полный TypeScript фронта лежит в `.js.map` рядом с бандлом ComfyUI; питон — в `execution.py` и `comfy_execution/`. Читать их, а не догадываться. Раздел «Работа со стыком ComfyUI» — список того, что уже стоило пользователю багов.

# Субагенты

Постоянное разрешение: запускать без спроса, когда объём окупает холодный старт (новый модуль с нуля, тесты, черновик документации, широкий поиск по репо). Ставить в известность фактом — «отдал субагенту X», — а не спрашивать заранее. Смысл — не гонять весь накопленный контекст через флагманскую модель ради генерации больших объёмов кода/текста. Окупается только крупный изолированный объём: новый модуль с нуля, тесты, черновик документации. Не окупается всё, где пересказ контекста длиннее самой правки.

- **Модель указывать явно — `model: sonnet`.** Обязательно, не рекомендация: без явного `model` субагент наследует Opus и экономии не даёт.
- **Промпт самодостаточен.** Субагент не видит нашу переписку: цель, пути к файлам, ограничения и критерий готовности — всё в промпте. Требовать краткий отчёт (что сделано, `путь:строка`, что осталось), без дампов файлов и полных листингов.
- **Отчёт проверять по коду** перед тем, как докладывать результат пользователю.
