# Порядок выпуска версии

Файл для того, кто ведёт разработку пака. В архив реестра не уезжает —
`docs/release/` исключён в `.comfyignore`.

Порядок шагов здесь не косметический: каждый пункт «сначала это, потом то»
оплачен конкретной поломкой, они перечислены в конце.

## Шаги

1. **`CHANGELOG.md` — новый раздел сверху.** Заголовок строго
   `## X.Y.Z (ГГГГ-ММ-ДД)`. По этому заголовку воркфлоу публикации вырезает
   текст для страницы релиза на GitHub: раздел от заголовка до следующего
   `## `. Формат заголовка сломается — релиз выйдет с пустым описанием.

2. **Номер версии в трёх местах.** `pyproject.toml` (`version`),
   `frontend/package.json` (`version`) и `frontend/package-lock.json` (там
   номер лежит дважды — в корне и в `packages[""]`). Лок проще не править
   руками: `npm install` в `frontend/` подтянет номер сам.

3. **Сборка фронтенда — после смены номера, не до.**

   ```
   cd frontend && npm run build
   ```

   Порядок именно такой, потому что `npm run build` записывает в
   `dist/.source-hash` отпечаток того, из чего собран бандл, а в этот
   отпечаток входит и `package-lock.json`. Соберёте до смены номера —
   отпечаток окажется от старого лока, и проверка `check:bundle` покраснеет
   на ровном месте.

4. **Проверки.**

   ```
   E:/AI/ComfyUI-Easy-Install/python_embeded/python.exe -m pytest
   ```

   ```
   cd frontend && npm run test:all
   ```

5. **Коммит.** Собранный `frontend/dist` идёт в том же коммите, что и смена
   версии, — он лежит в гите и именно он уезжает в реестр.

6. **Тег и пуш.**

   ```
   git tag -a vX.Y.Z -m "Release X.Y.Z"
   ```

   ```
   git push origin main && git push origin vX.Y.Z
   ```

7. **Дальше воркфлоу сам.** Пуш тега `v*` запускает
   `.github/workflows/publish.yml`: он собирает фронтенд заново, публикует
   пакет в реестр ComfyUI и создаёт релиз на GitHub с текстом из
   `CHANGELOG.md`. Ничего вручную создавать не нужно.

8. **Проверить результат.**

   - CI на `main` зелёный и воркфлоу публикации отработал:
     https://github.com/FiL-Design-Ai/FiL_Design_ImageMind/actions
   - Релиз появился:
     https://github.com/FiL-Design-Ai/FiL_Design_ImageMind/releases
   - Версия в реестре активна:

     ```
     curl -s https://api.comfy.org/nodes/FiL_Design_ImageMind/versions
     ```

     У новой версии должно быть `"status": "NodeVersionStatusActive"`.
     `NodeVersionStatusFlagged` — автоматическая проверка безопасности сочла
     содержимое архива подозрительным, см. грабли ниже.

## Грабли, уже стоившие выпуска

- **Сборка до смены номера версии.** Номер версии попадает в
  `package-lock.json`, лок входит в отпечаток исходников, отпечаток
  сверяется в CI. Релиз 1.1.2 вышел с красным CI ровно поэтому: бандл был
  собран правильный, но отпечаток описывал предыдущий лок.

- **Сорсмап должен уезжать в архив.** `frontend/dist/fil_design_imagemind.js` —
  это 700 КБ минифицированного кода, а `frontend/src/` в архив не идёт. Без
  карты (`.js.map`) реестр видит нечитаемый код и помечает версию как
  подозрительную: 1.0.0 карту возил и остался Active, 1.1.0 первым её
  исключил и получил Flagged, 1.1.1 унаследовал. Подробности — в комментарии
  внутри `.comfyignore`, там же запрет исключать её снова.

- **Тег — это не релиз.** Тег только помечает коммит. Страница релиза на
  GitHub создаётся отдельно; до августа 2026 её не создавал никто, и пять
  тегов подряд оставили раздел Releases пустым. Теперь этим занимается шаг
  в `publish.yml` — но если он когда-нибудь отвалится, пустая страница
  Releases будет означать именно это, а не сбой публикации в реестр.

- **Страница издателя в реестре врёт про версию.** На
  `registry.comfy.org/publishers/...` в шапке показывается самая старая
  версия, а не последняя: реестр отдаёт этой странице пустое поле «последняя
  версия», и она берёт крайний элемент списка. Реальное положение дел — на
  публичной карточке `registry.comfy.org/nodes/FiL_Design_ImageMind` и в API.
  Чинить нечего, это баг на их стороне.

- **Версию из реестра нельзя перевыпустить.** Опубликованная версия
  неизменяема. Ошиблись — только новый номер. Старую можно пометить
  устаревшей: публичная карточка пакета → у версии `More` → тумблер
  `Deprecate version`; пользователи увидят предупреждение и предложение
  обновиться.
