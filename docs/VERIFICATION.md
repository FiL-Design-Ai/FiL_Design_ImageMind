# Лестница проверок

Файл для того, кто ведёт разработку пака. В архив реестра не уезжает —
исключён в `.comfyignore`.

Правило одной фразой: **изменение проверено, когда прошли все ступени его
слоя и все ступени ниже.** Не уверен, какой у тебя слой, — бери на ступень
выше: лишний прогон дешевле бага на чужой машине.

## Зачем вообще правило

Автотесты ловят не всё, и это оплачено конкретными поломками:

- pytest работает в песочнице: `tests/conftest.py` принудительно ставит
  `--cpu` и подменяет LLM-клиент стабом. Реальные ответы API, таймауты,
  rate limits, GPU/VRAM и настоящие модели остаются за пределами покрытия.
- Юнит-тест проверяет только сценарии, которые были придуманы заранее.
  Комбинации графа, которые соберёт пользователь, не ограничены ничем.
- Настоящий ComfyUI-сервер нигде в тестах не запускается: ни `graphToPrompt`,
  ни кэширование исполнения (`CacheKeySetInputSignature`), ни DOM widget
  host. Баг кэша seed'а жил именно там — DOM-виджет сериализовал блоб
  панельного состояния в prompt payload, кэш хэшировал его в ключ и
  переисполнял ноду на каждый queue; нашли и подтвердили только живым
  прогоном.

## Ступени

| # | Что меняли | Чем проверить |
|---|---|---|
| 1 | Python-логика нод и `common/` | `ruff check` + точечный `pytest tests/test_<имя>.py`, затем полный `pytest` (команда — в `docs/release/RELEASE_CHECKLIST.md`) |
| 2 | Виджеты / `INPUT_TYPES` ноды | `npm run gen:contracts`, затем контрактные тесты обеих сторон (`pytest tests/test_node_contracts.py`, фронт-сьют из ступени 3) |
| 3 | Фронтенд: Vue, TS, nodes2 | `cd frontend && npm run test:all` |
| 4 | Всё, что попадает в `frontend/dist` | `npm run build` + `npm run check:bundle` (sourceHash-страж) |
| 5 | Поведение в живом ComfyUI: исполнение, кэш, сериализация виджетов, Nodes 2.0 | живой прогон в UI |
| 6 | Релиз | `docs/release/RELEASE_CHECKLIST.md` |

Менял несколько слоёв — бери высшую из затронутых ступеней и всё ниже неё.

Ступень 5 **обязательна**, если изменение касается исполнения, кэша,
сериализации виджетов или DOM-слоя: это зона, где автотестов физически нет.
Если живой прогон выявил баг, который нельзя покрыть автотестом (например,
он живёт в ядре ComfyUI), запись в CHANGELOG помечается «проверено вручную»
с шагами воспроизведения.

## Три железных дополнения

1. **Каждый баг-фикс — с регресс-тестом.** Тест обязан падать без фикса и
   проходить с ним. Фикс без теста — это отложенный повтор.
2. **Правка виджетов без `npm run gen:contracts` не считается законченной.**
   `common/contracts/` — единый источник правды для обеих сторон.
3. **Проверки ступеней 1–4 запускаются до коммита, не после.** pre-commit
   (ruff + bandit + валидаторы) — это пол, а не потолок.
